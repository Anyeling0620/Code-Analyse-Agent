# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

主要用户是开发者与工程师。他们把工作台当作日常代码分析工具：接入一个 Git 仓库或本机项目路径，读结构化的项目分析报告，针对当前项目连续追问，连接业务库生成只读报表。使用场景通常是一段持续的工作会话，屏幕以桌面为主，也会在手机上查看分享链接或继续简单追问。

## Product Purpose

Repo Agent 把“读懂一个代码仓库”变成一次可追问的分析过程。它自动拉取/挂载仓库、建立按项目隔离的语义索引，再通过会调用工具的 Agent 链路产出带 Mermaid 图的结构化 Markdown 报告、项目问答与数据库报表。成功意味着工程师不用先花几小时翻目录，就能得到可验证、可继续深挖的结论。

## Positioning

项目级语义索引与多 Agent 工具链绑定在同一条可恢复的 run 上：回答过程中能实际执行仓库拉取、代码检索、文件读取、终端命令与数据库只读查询，并在断线、刷新、审批中断后从同一条 run 继续。这不是一次性代码问答，而是带执行证据、可回放、可分享的分析工作台。

## Operating Context

- 一次分析可能持续很久，报告包含多级标题、表格、代码块与 Mermaid 图。
- 工具调用会穿插在回答中间，用户可能需要展开查看参数与结果。
- 高危终端命令会触发审批中断，用户必须在弹窗中批准或拒绝后才能继续。
- 会话历史重要：用户会来回切换、分享只读快照、导出项目分析为 Markdown/PDF。
- 会话里同时出现账号身份、运行状态、成本/配额与 trace 等元信息。
- 界面语言为中文；技术名词、代码与模型输出保持原文。

## Capabilities and Constraints

- 仓库分析：输出固定 8 节 Markdown 报告，含 Mermaid 图。
- 项目问答：针对当前项目连续追问。
- 数据库报表：只读 SQL，中文 Markdown 报表。
- 项目级 RAG：Milvus collection 按项目隔离。
- 工具调用：终端、HTTP、项目扫描/搜索、文件读取、Git 拉取、RAG 检索、MCP 外部工具。
- 流式 SSE 输出；断线按 Last-Event-ID 续传；审批中断恢复；崩溃续跑。
- 账号密码登录 + 游客免密登录；按用户成本与每日额度统计。
- 会话列表/详情/删除、只读分享、执行链路查看、Markdown/PDF 导出。
- 技术约束：React 18 + Vite + TypeScript，现有组件与接口不可破坏；SSE 长连接；移动端可用。
- 未决：品牌视觉、图标体系、字体授权与是否需要深色主题。

## Brand Commitments

现有产品名为 Repo Agent（浏览器标题与侧栏）。界面使用中文，语气直接、偏工程化。除此之外没有已确认的商标、色板、字体或视觉资产约束。

## Evidence on Hand

仓库 README 中的能力表、架构 Mermaid 图、API 概览，以及现有 Web 前端的真实界面与中文文案。没有可引用的客户 logo、案例、基准数据或宣传素材；未来工作不得编造这些内容。

## Product Principles

1. 证据优先：结论旁边应能找到工具调用与执行链路，而不是只给一个漂亮答案。
2. 可恢复：长任务、断线、审批中断都不能让用户丢失上下文。
3. 阅读优先：报告是产品的主要产出，排版、代码、表格与图表必须经得起长时间阅读。
4. 工具感而非营销感：界面服务于正在工作的工程师，克制、精确、不表演。
5. 分享与导出是一等能力：分析结果需要离开工作台也能读。

## Accessibility & Inclusion

移动端浏览器需要完成登录、查看会话、阅读报告和发送简单追问；键盘操作与可见焦点状态必须保留。
